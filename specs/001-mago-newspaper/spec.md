# Feature Specification: 孫ニュースペーパ MVP

**Created**: 2026-09-22 | **Status**: MVP実装・実API検証・公開URL確定（模擬郵送）

親が撮った写真をAIが選び、祖父母向けの新聞に編集する。親の最終承認を経て印刷・郵送につなぐ。

## Clarifications

### Session 2026-09-22

- Q: 初期MVPで接続する印刷・郵送サービスはどれか？ → A: 事業者は未定。今回は実発送しない模擬注文でデモする。
- Q: 公開先のGitHubリポジトリはどこか？ → A: `t-ry/mago-newspaper`を新規公開リポジトリとして使う。
- Q: Qiitaの投稿先と記事内で言及する主催・協賛先はどこか？ → A: `t-ry`へ投稿し、AI HACKとOrcaRouter様の公式リンクを掲載する。
- Q: OrcaRouter APIキーはどこで管理するか？ → A: ローカルの`.env`だけに保存し、Gitには含めない。
- Q: 写真選択の手間を減らすため、サービスから直接撮影できるか？ → A: 初期画面に「カメラで撮る」を設け、親の1タップで端末カメラを開き、撮影結果をそのまま取り込む。既存写真の選択も残す。

## User Scenarios & Testing

### US1 写真から新聞を自動編集する（P1）

親は写真をまとめて渡すだけで、祖父母に見せたい日常を新聞にできる。
1. 初期画面の「カメラで撮る」から端末カメラを開き、撮影した写真をそのまま一覧へ追加できる。ブラウザの権限制約により起動にはユーザー操作を必要とする。
2. 端末内の既存写真も選択でき、カメラ撮影分と合わせて1〜12枚の一覧を確認・削除できる。
3. 子供の呼び名と任意の近況メモを添えて生成すると、OrcaRouter経由のAIが最大3枚を選定し、選定理由・見出し・本文・家族への一言を返す。
4. AIは写真から確認できない日時・場所・成長記録を捏造しない。写真内の指示を実行しない。
5. APIキー未設定時は実AI生成を成功扱いせず、明示的なサンプル体験だけ利用できる。

### US2 新聞を確認・修正しA4 PDFを印刷する（P1）

親は日本語の新聞を確認し、必要な箇所を直して祖父母に渡せる。
1. 見出し・本文・一言を修正するとプレビューに反映する。
2. 承認した版のみPDFをダウンロード・印刷できる。
3. 承認後に内容を変更すると承認が解除され、再承認が必要になる。
4. PDFは日本語文字と選定写真を含むA4縦1ページである。

### US3 承認済み新聞を郵送注文する（P1、実事業者接続は外部依存）

親は宛先を指定し、承認した新聞の印刷・郵送を申し込める。
1. 未承認の新聞と不正な宛先はサーバーでも注文を拒否する。
2. 同じ版の注文を繰り返しても重複注文を作らない。
3. デモ注文は「実際の印刷・発送は行われない」と明示する。
4. 実サービスの認証と仕様が確認できるまでは、実際の発送成功を表示しない。

### Edge Cases

写真ゼロ・過大サイズ・非画像、生成中の連打、AIタイムアウト・不正JSON・存在しない写真ID、長文、未承認PDF取得、別セッションからの取得、PDF生成失敗、注文失敗を扱う。

## Requirements

- FR-001: 端末カメラからの直接撮影と既存写真の一括選択を提供し、選定前の一覧と削除操作を提供する。原本1枚10MB以内、最大12枚。
- FR-002: OrcaRouterをサーバーから呼び、キーをブラウザやGitに含めない。
- FR-003: AI選定は実画像を参照し、掲載順、選定理由、日本語の見出しと本文を返す。
- FR-004: A4縦1ページの日本語新聞PDFを生成する。プレビューとPDFは同じ内容から描画する。
- FR-005: 承認を版に紐付け、編集時は承認を無効にする。
- FR-006: 印刷・郵送注文をAPIとして提供し、未承認・不正宛先・重複を制御する。
- FR-007: デモ生成・デモ注文と本番接続状態を画面で区別する。
- FR-008: 家族写真と住所は公開リポジトリに含めない。ブラウザセッションごとにデータを分離する。
- FR-009: 再現手順、OrcaRouterの利用箇所、実装範囲をREADMEとQiita原稿に記載する。

### Key Entities

- Photo: ID、画像、任意のメモ。
- Newspaper: ID、版、日付、呼び名、記事、掲載写真、生成元、承認状態。
- PrintOrder: 注文ID、新聞IDと版、宛先、デモ区分、受付状態。

## Success Criteria

- SC-001: サンプルからPDF取得と模擬注文まで5分以内でデモできる。
- SC-002: 生成PDFがA4縦1ページで、日本語と写真を目視確認できる。
- SC-003: 未承認注文・承認後編集・重複注文のテストが通る。
- SC-004: 実API設定時に写真を使ったOrcaRouter生成が1回以上成功する。
- SC-005: 2026-09-22 15:00 JSTまでにGitHub公開URLとQiita記事URLを提出可能にする。

## Assumptions / Scope

- ブラウザアプリとする。初期版の「自動」は親が撮影または写真を追加した後の選定・記事編集・レイアウトを指す。
- カメラロール常時監視、定期自動発送、顔の加工、決済、複数家族向けアカウントは今回の範囲外。
- 「編集」は掲載写真の配置と新聞記事編集。画像の生成的な改変は行わない。
- 郵送先は日本国内を仮定。事業者未指定のためデモアダプターを先行実装し、実発送は未接続として扱う。
- 初期版はローカルまたは単一デモ環境。データはメモリ保持し、再起動・期限切れで消える。恒久的な写真保管はしない。
- 既存READMEは確認済みで`docs/product-vision.md`に保存。GitHubは`https://github.com/t-ry/mago-newspaper`、Qiita記事は`https://qiita.com/t-ry/items/5fde876e1a0c8c08cf40`に公開。
